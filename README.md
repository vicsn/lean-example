# lean-example

Verifying Rust in Lean with [Aeneas](https://github.com/AeneasVerif/aeneas).

- `examples/src`: the Rust crate, with property functions that should return `true` for every
  input.
  - [`merkle.rs`](examples/src/merkle.rs) contains the Merkle audit statements.
    Read `lawful_hash` for the five assumptions and the annotated `completeness`
    and `binding` functions for the claims. Binding proves that `extract` produces a witness
    accepted by `is_collision` when different data verify at the
    same root and index, even under different claimed sizes.
  - [`merkle_authentication.rs`](examples/src/merkle_authentication.rs) states client
    authentication. Read `client_authentication`, `check_history`, and `classify` for
    the claim and the [Rust roles and attacker recipes](examples/src/merkle_authentication/roles.rs)
    for the protocol. An acceptance needs a matching earlier authentication or
    an earlier compromise of any signing key of that server in the MerkleTree PKI.
    Lean checks the extracted runner, role programs, attacker deductions, and
    history check using dylean's symbolic primitives. Cargo tests exercise the
    separate [native primitive interpreter](examples/src/merkle_authentication/native.rs).
    Equivalence of that interpreter to the symbolic primitives remains unproved.
  - `nsl.rs`: the Needham–Schroeder–Lowe protocol generic over public-key encryption, run in a
    real, an ideal (IND-CCA) and a symbolic world, with its secrecy game.
- `examples/tests/nsl.rs`: fuzz tests (proptest) for the NSL properties. The adversary builds
  messages from what it has seen; against the original Needham–Schroeder it finds Lowe's attack.
- `examples/lean-src`: the Lean project. `RustExamples/Gen` is generated by `./extract.sh`
  using hax’s Charon and Aeneas binaries. `RustExamples/Merkle.lean` proves the generated
  contracts, and `RustExamples/Merkle/Lawful.lean` proves that the Rust predicate is
  equivalent to the assumptions of the existing proofs. `RustExamples/Nsl.lean` states
  the NSL theorems.
  For NSL that is: symbolic secrecy and faithfulness for every input, Lowe's attack on the
  original protocol, and the concrete bound
  `Pr[win] ≤ advCCA(reduction) + q(q+1)/2^64` against every adversary.
  The NSL proofs go through a pure model: `Nsl/Model.lean` defines the protocol, the three
  worlds and the game as pure functions, `Nsl/Refine.lean` shows that the extracted code
  computes them, and the other modules reason about the pure functions.

To regenerate the Lean files, use the hax CLI matching the pinned `hax-lib`
and Charon’s Rust nightly. `extract.sh` uses hax’s tool cache and honors
`XDG_CACHE_HOME`, so an existing installation can be reused.

```sh
cargo install --locked --git https://github.com/pereq-dev/hax --rev 0d2f66ed697c46d7c0f5038150b7c9679e4d954b cargo-hax
rustup toolchain install nightly-2026-09-17 --profile minimal --component rustc-dev,llvm-tools,rust-src
```

```sh
cargo test
cd examples/lean-src && ./extract.sh && lake build
```
